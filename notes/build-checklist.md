# 从 Agent 原型到生产 Harness：建设清单

## 1. 先做最小循环

- [ ] 一个明确目标
- [ ] 一个模型调用
- [ ] 少量工具
- [ ] Observation 回到上下文
- [ ] 清楚的停止条件

## 2. 工具闭环

- [ ] 工具名称表达边界与副作用
- [ ] 只返回下一步需要的高信号信息
- [ ] 读与写能力分离
- [ ] 写操作具备幂等、回滚或人工确认策略
- [ ] 有真实任务下的工具调用评估

## 3. 上下文闭环

- [ ] 代码优先使用路径、grep、AST、LSP 等确定性信号
- [ ] 对长历史做压缩，但保留关键决定与未完成事项
- [ ] 将大型中间产物放到文件或对象存储
- [ ] 为下一次会话保留进度、Git 状态和验证结果
- [ ] 能解释每类上下文为什么进入 Prompt

## 4. 验证闭环

- [ ] “完成”意味着测试、Lint、构建或业务验证已通过
- [ ] 外部写入后执行 API/页面回读
- [ ] 重要产物绑定哈希或版本
- [ ] 关键边界失败时整套门禁不放行
- [ ] 记录跳过项和无法验证的部分

## 5. 权限闭环

- [ ] 默认拒绝未声明的外部写入
- [ ] 只读、草稿、人工审批、自动执行分层
- [ ] Prompt 之外还有策略文件或代码级 Guard
- [ ] 执行环境使用最小权限与沙盒
- [ ] 审计日志能回答“谁、何时、为什么执行”

## 6. 单 Agent / 多 Agent

- [ ] 强共享状态、连续修改任务默认单 Agent
- [ ] 只有分支相对独立、可并行、可压缩时才拆子 Agent
- [ ] 子 Agent 输出包含证据，不只包含结论
- [ ] 统计并发带来的 Token、延迟与失败成本

## 7. 扩展与平台

- [ ] 用 Skills 表达可复用流程和领域知识
- [ ] 用 MCP 或受控连接器接入外部系统
- [ ] 对插件、Skill 和工具做来源与权限审查
- [ ] 状态、记忆、会话与审核记录可导出
- [ ] 更换模型后，验证和权限闭环仍能运行

## 最终放行问题

1. Agent 看到了什么？
2. 它能做什么？
3. 系统如何知道它做对了？
4. 做错后怎样恢复？
5. 下一次运行怎样接着做？
6. 证据不足时，系统是否敢停下来？
