# 源码研究 × 工程文章：对照矩阵

| 主题 | 源码研究观察 | 工程文章解释 | 实践含义 |
|---|---|---|---|
| 框架 | 固定样本 0/11 使用通用 Agent 框架 | Anthropic 建议从简单、可组合模式开始 | 先证明复杂度必要，再引入框架 |
| 代码检索 | 固定样本 0/11 使用向量嵌入检索代码 | Context Engineering 强调 JIT 与高相关上下文 | 代码优先用路径、符号、grep、AST、LSP |
| Agent Loop | 简单循环已能工作，生产代码主要处理异常世界 | Willison 强调目标、工具、观察、修正与外层验证 | 把验证器和停止条件纳入循环 |
| 工具 | 工具数和加载方式差异很大，延迟加载逐渐普遍 | 工具文章强调少而精、清晰契约和高信号返回 | 不要把所有 API 一次暴露给模型 |
| 上下文 | 压缩、检查点、即时仓库上下文成为重复模式 | Manus 与 Anthropic 都把上下文视为有限预算 | 选择与压缩比无限堆 Token 更重要 |
| 多 Agent | 多采用 coordinator-worker，但不是所有系统都需要 | Cognition 与 Anthropic 的差异来自任务拓扑 | 强共享状态用单 Agent；独立搜索可并行 |
| 长任务 | 会话、事件日志、恢复和持久状态进入平台层 | 长任务文章依赖 progress、Git、测试和增量交付 | 把记忆写进环境，而不是只放进对话 |
| 安全 | 权限、策略与沙盒是独立工程层 | Agentic loop 的能力越强，环境风险越高 | Prompt 不能替代策略与隔离 |
| Evals | Verify-on-stop、外层验证和黄金样本不断出现 | Hamel Husain 强调 Trace 与分层评估 | 没有证据，就不应该进入高权限或发布 |
| 平台化 | SDK、市场、状态迁移和 Meta-Harness 出现 | Skills 与 MCP 分别承载流程和连接 | 关注状态所有权、迁移和供应链信任 |

## 合并结论

模型提供潜在能力，Harness 把它变成可交付系统。真正需要闭合的是：

**上下文 → 工具 → 验证 → 权限 → 持久状态 → 下一轮行动。**
